# 文档治理

状态：已采用

日期：2026-08-27

## 目标

RadishNexus 当前以文档冻结产品和架构边界。文档治理的目标不是增加格式，而是让读者知道哪份文件是权威结论、哪份只是当前状态，以及变更时应同步什么。

## 文档分层

| 层级 | 内容 | 变更方式 |
| --- | --- | --- |
| 法律层 | `LICENSE`、`SECURITY.md` | 谨慎修改；必要时专业复核 |
| 稳定真相层 | 产品定义、领域模型、决策基线、架构原则 | 说明理由、影响和迁移；重大取舍写 ADR |
| 决策记录层 | `docs/adr/` | 接受后不重写历史；用新 ADR 替代旧结论 |
| 当前状态层 | `docs/status/current.md`、路线图 | 可随阶段推进更新，不反向覆盖稳定真相 |
| 协作层 | 贡献指南、治理文档、模板、检查器 | 与实际仓库策略同步 |
| 实现层 | 模块 README、API、运行和运维说明 | 与代码同 PR 更新 |

## 真相源

- 产品服务谁、解决什么和明确不做什么：`docs/product-definition.md`。
- 核心对象、关系和权限语义：`docs/domain-model.md`。
- 已确认且不得静默漂移的产品决策：`docs/decision-baseline.md`。
- 最薄纵向实验和验收：`docs/golden-path.md`。
- 稳定架构边界：`docs/architecture/`。
- 许可策略：根 `LICENSE` 优先，`docs/licensing-strategy.md` 负责解释布局和产品原则。
- 当前阶段、下一步和开放问题：`docs/status/current.md`。
- 工程/治理取舍：`docs/adr/`。
- 仓库工作方式：`docs/governance/` 与根协作文件。

README 是导航入口，不应成为所有结论的第二份副本。

## 何时写 ADR

满足任一条件时应写 ADR：

- 改变长期分支、合并、发布或兼容策略；
- 选择会约束多个模块的框架、协议、存储或运行模型；
- 改变安全、权限、数据所有权或插件隔离边界；
- 推翻已接受的工程决策；
- 方案取舍需要让未来维护者知道“为什么”。

局部实现细节、可轻易回退的重构和单次缺陷修复通常不需要 ADR。

ADR 使用四位编号，状态至少包含“提议”“已接受”“已替代”或“已拒绝”。已接受 ADR 只修复事实或链接错误；决策变化通过新 ADR 的 `Supersedes` 关系表达。

## 写作和链接规则

- 默认使用中文，专有名词和协议名保留英文。
- 使用仓库相对链接，不写本机用户目录、文件协议 URL 或会话私有链接。
- 清楚区分“已实现”“已决定”“候选方案”和“未来可能”。
- 示例必须标明是否可执行；命令应从仓库根运行，或写明工作目录。
- 不复制大段规则；链接到真相源并只保留必要摘要。
- 文档明显增长、职责混杂或超过约 400 行时，应评估拆分，但不以行数机械决定结构。

## 更新矩阵

| 发生变化 | 同步检查 |
| --- | --- |
| 产品定位或非目标 | 产品定义、README、决策基线、当前状态 |
| 领域语义 | 领域模型、决策基线、API/事件契约、Golden Path |
| 架构选择 | ADR、架构文档、工程标准、当前状态 |
| 分支或 CI 门禁 | ADR、治理基线、Ruleset、Workflow、检查器、贡献指南 |
| 许可证 | `LICENSE`、许可策略、README、贡献指南 |
| 当前阶段 | 只更新当前状态和必要路线图，不改写历史决策 |

## 审查清单

文档 PR 应确认：

- 结论写入了正确真相源；
- 没有把候选方案描述成已经实现；
- 相对链接和标题仍有效；
- 没有本机绝对路径、私密会话链接或凭据；
- 与规则、模板、代码和状态文件不存在明显冲突；
- 已运行仓库检查器。
