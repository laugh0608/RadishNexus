# 工程标准

状态：初始基线

日期：2026-08-27

## 总体原则

- 先完成 Golden Path 所需的最小模块化单体，不以服务数量衡量成熟度。
- 业务不变量进入领域层，传输层、数据库层和 UI 不各自发明一套含义。
- API、事件、权限和数据库迁移是兼容性边界，修改时必须说明升级与回退。
- 失败应可观察、可恢复；不能用吞错、无限重试或静默降级伪装成功。
- 默认最小权限。私密内容在搜索、通知、Activity、导出和 AI 上下文中保持相同访问边界。
- 不为未来猜测建立抽象；出现第二个真实用例后再提炼通用接口。

## Go 服务端

- Go 是主要业务实现语言；按领域模块组织模块化单体，而不是按 HTTP/数据库技术层切成相互穿透的目录。
- 提交前运行 `gofmt`、相关 `go test` 和适用的 `go vet`。
- I/O 和跨边界调用接收 `context.Context`，超时、取消和幂等语义应显式。
- 错误保留上下文和可判定类型，不依赖字符串匹配实现业务分支。
- 数据库事务只包围需要原子性的最小范围；外部网络调用不放入长事务。
- 包级可变状态和隐式单例应避免；依赖通过清晰构造边界传入。

具体 Web 框架和数据访问库尚未冻结，选型必须通过原型和 ADR，不写入通用规则假装已经决定。

## React 与 TypeScript

- Web App 是第一产品形态，使用严格 TypeScript；不得用广泛 `any` 绕过契约问题。
- API 类型优先从版本化契约生成或集中维护，不在页面中散布无类型 `fetch`。
- 服务端状态、客户端交互状态和编辑草稿状态分开建模；缓存不能成为新的业务真相源。
- 组件必须考虑键盘操作、语义标签、焦点、加载、空态、错误和权限拒绝。
- Nexus View 等复杂页面先保证对象关系和信息层级清晰，再添加动画和装饰。
- 破坏性或高风险操作必须显示对象、范围、后果和可恢复性，不能只提供通用确认框。

具体状态管理、路由、编辑器和组件库属于尚未冻结事项。

## Rust

- Rust 只进入具有明确隔离、性能、WASM、加密、索引或跨端复用收益的边界。
- 提交前运行 `cargo fmt --all`、相关测试和适用的 `cargo clippy`。
- 默认禁止 `unsafe`；确有必要时需隔离在最小模块，写明安全不变量并通过 ADR 审查。
- 不用 Rust 重写普通业务模块来追求技术一致性。

## Flutter

Flutter 客户端在 Web 达到独立阶段门槛后再启动。启动后：

- 复用 API、协议和设计 Token，不强求与 React 共享页面实现；
- 提交前运行 `dart format`、`flutter analyze` 和相关测试；
- 离线缓存和同步必须有明确冲突、权限撤销和数据清理语义；
- 不因客户端需要而削弱服务端授权检查。

## API、事件与数据

- 对外和跨模块标识使用稳定 ID，不用名称、URL 或数据库行序替代身份。
- 时间使用明确时区和精度；存储 UTC，展示按用户/工作区规则转换。
- 事件 envelope 至少包含事件 ID、类型、版本、发生时间、主体、来源和可追踪上下文。
- 消费者必须按事件 ID 幂等处理；重试、乱序和重复是正常输入，不是异常假设。
- Schema 变更优先向前/向后兼容；破坏性迁移提供阶段方案、验证和回滚限制。
- EntityLink 记录关系类型、来源、创建者和时间；Activity 可重建，不反向成为业务事实。
- CI Run 和 Deployment 使用不同实体、权限和生命周期。

## 权限、安全与插件

- 授权检查发生在服务端对象边界，UI 隐藏不是权限控制。
- 搜索索引、通知、反向链接、审计和导出都不得泄露目标对象存在性或内容。
- 插件默认无权限，通过清单声明最小能力；安装、升级和权限变化需要可审阅差异。
- Secret 不进入插件包、日志、事件、Activity 或可移植上下文包。
- Webhook 验证来源并防重放；副作用按交付 ID 幂等，外部失败使用有界重试和死信/人工恢复路径。
- SSRF、任意 URL、模板注入和插件网络访问必须有显式控制。
- AI 生成内容只能作为草稿或建议；确认 Decision、改变状态和触发外部操作需要有权限的人确认并留下审计记录。

## 测试

每个变更至少覆盖与风险匹配的层级：

- 领域不变量：快速、确定性的单元测试；
- 数据库、权限和事件投影：真实边界的集成测试；
- Golden Path：覆盖“讨论 → Decision → Ticket → CI Run → Deployment → 时间线”的关键场景；
- 外部集成：契约测试、重复交付、超时、重试和失效凭据；
- UI：核心交互、权限拒绝、错误/空态和可访问性；
- 迁移与恢复：备份、升级、失败中断和回滚限制。

测试不得依赖真实个人账号、生产 Secret 或不可重复的外部环境。

## 依赖与生成内容

- 只在能明确降低风险或维护成本时引入依赖；检查许可证、维护状态和供应链风险。
- 依赖版本和锁文件随变更提交，禁止从浮动分支或未固定下载地址执行构建代码。
- 生成内容必须有来源、生成命令和漂移检查；能在 CI 稳定生成时不要手工维护副本。
- 开放 SDK、协议和插件进入各自目录时必须同时建立独立许可证边界。

## CI 演进

新语言或应用进入仓库时，应把其最小可信检查接入 `Candidate Quality`，同时更新本文件、贡献指南、忽略规则和本地入口。只有已经稳定运行的检查才能成为 `master` 必需门禁。
