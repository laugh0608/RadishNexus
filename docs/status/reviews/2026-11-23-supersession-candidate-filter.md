# 替代旧结论的候选筛选验证

2026-11-23，项目管理员与一名有决策权的成员在隔离 Chrome 会话中访问本机 HTTPS 和真实 PostgreSQL。通过正式命令在同一受限项目中准备 34 条决策，覆盖待确认、已确认、已拒绝和已被替代。成员在 430 像素宽的页面进入新结论详情，打开「选择旧结论」。[替代合同](../../adr/0049-decision-supersession.md) · [状态筛选合同](../../adr/0063-project-decision-status-filter.md)

| 场景 | 观察到的结果 |
| --- | --- |
| 默认与筛选分页 | 全部列表的两页合计显示四种状态。从第二页勾选「只看已确认」后回到筛选首页，31 条已确认决策分两页显示（25 条和 6 条）。前后翻页保留条件，新结论自身不可选。重新进入详情后打开选择器，默认显示全部。 |
| 重选相同候选 | 成员核对第二页的旧结论后，管理员用另一条结论将其替代。成员再次选择同一候选，页面重读详情并显示已被替代的提示。提交控件消失，成员没有发出替代 POST。重新读取候选时回到已确认首页。 |
| 核对后发生竞争 | 管理员抢先替代另一条已核对的候选。成员的原提交收到真实 409，页面重新读取双方详情，提示旧结论已被替代。重新选择第三条候选并确认后提交成功。重读验证竞争中的旧结论版本为 3，新结论在成功提交后为版本 3，第三条候选状态为已被替代。 |
| 翻页时失去项目读权 | 管理员移除该成员后，已确认列表的下一页请求返回 404，页面清除了决策详情及候选列表，显示权限变化提示。 |

页面回归测试还覆盖切换筛选时放弃上一页请求、丢弃旧理由和确认，以及已提交但响应未知时按原版本、原理由、原操作标识重试。[回归测试](../../../web/src/collaboration/DecisionSupersession.test.tsx)
