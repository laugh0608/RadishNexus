2026-11-08，以登记的 `127ba0c` app、operations 和 Git 配置启动一次性 OrbStack 回环 HTTPS 实例，重新核对镜像 ID、配置校验值、schema 025 和数据库角色。Agent 使用 Chrome 156.0.8078.80 的四个独立进程操作三个合成账号，分别为原 Workspace owner、接任成员、受限 Project 的普通成员。其中普通成员同时持有两个独立会话。证书公钥信任仅限本次浏览器进程。

| T04 场景 | 结果 | 实测证据 |
| --- | --- | --- |
| 账号恢复 | 通过 | 正式 `account-recover inspect → apply → status` 核对目标并返回同一 `applied` 记录。两个旧浏览器会话查询 Session 均为 `401`，刷新回到登录页，已建立的 SSE 订阅关闭。旧密码返回 `401`，新密码可在两个浏览器重登。用户 ID、Workspace 成员角色、受限频道权限和原消息作者均保持 |

| 新归档的 dump 摘要与 manifest 不符，较早的已验证备份之后还有确认写入 | 部署负责人保持停写，通过约定的私密运维渠道报告工具版本、错误类别和脱敏证据，记录最后确认写入、未决请求和有效备份点。若只能使用较早备份，由数据责任人确认实际缺口与取舍，再用匹配工件恢复到独立空目标并复验。重新开放前确认复验结果和唯一可写实例 |
| 试用到期，参与主体申请取回一个 Project 的协作记录，书面材料尚未确认到期后的取回范围 | 先停止约定范围的访问并保管证据。取回决定保持待确认，先复核接收人、用途、时间和所需运行权限。获准后按单 Project 上下文包流程核对范围和校验值，确认接收后按约定记录保留或处置。若获准范围要求整库，以受控备份和匹配工件的隔离空目标恢复交付 |

四个案例均能从现有材料找到处理角色、证据字段和下一步条件。正式试用宿主、责任人、联系与退出安排仍待填写，目标宿主 T03、T06、T07 以及 T04、R08、U27 的独立验收状态仍为待验证。

## 本机 T08 单 Project 数据取回

2026-11-08，以登记的 `127ba0c` app、operations、Git 配置和 `nexus-context` 启动两个本机 OrbStack 回环 HTTPS 实例。源端建立一个交付范围内的受限 Project 和一个范围外的受限 Project。接收端只有初始化的 Workspace 与接收账号，容器、数据库 volume 和 PostgreSQL system identifier 与源端均不同。全部账号与数据均为合成样本。

| 检查 | 实测结果 |
| --- | --- |
| 停止参与者访问 | 普通成员原先能读获准频道，尝试导出返回 `404`。通过正式成员管理命令暂停后，同一会话的频道读取及导出均返回 `404`，全局 Session 仍有效。源端保留 Project admin 的受控导出入口 |
| 导出与核对交付副本 | `nexus-context export` 生成 `project-collaboration-v6`，对实际交付副本执行 `inspect` 得到相同包摘要。包内有 8 个对象、11 条历史、2 个 Document 版本、2 个历史作者，并保留 Decision 复核。扫描未发现范围外 Project、频道、消息标识和正文标记，合成登录凭据也未出现。改动副本的 `objects.jsonl` 后，`inspect` 拒绝读取 |
| 关闭源入口与确认导入 | 生成副本后停止源 app 和 Caddy，源 HTTPS 连接被拒绝。接收侧 `prepare` 后项目列表仍为空，回执为 `not_observed`。错误确认摘要被 CLI 拒绝，目标项目列表仍为空。按精确摘要执行 `apply`，再用原操作编号查询 `result`，得到同一 `applied` 回执 |
| 接收侧读回与权限 | 接收方发现新 ID 的受限 Project，经正式 HTTPS API 读回 Thread、Decision 及原复核、进行中的 Ticket 和 Document 第 2 版，来源标记为已导入。接收侧普通成员看不到该 Project，相关直达读取均返回 `404`。数据库核对 2 个历史作者均为禁用账号，无本地登录凭据 |

回执查询遇到 `429` 后，等待现有登录限流窗口，再按原操作编号重查。项目列表断言按正式响应的 `ref.id` 修正后，从干净实例完整复跑通过。两端容器、网络、volume、临时凭据、包副本和导入计划均已清理。正式 T08 仍需实际确认退出窗口、接收人、数据范围、取回所需授权和保留或处置安排。 [试用交接单](../../trial-support.md#首批试用交接单) · [上下文包手册](../../../deploy/context-package.md)
