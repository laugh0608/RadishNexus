# 从工单关联执行讨论的验证

2026-11-23，两个隔离的合成账号通过本机 HTTPS 访问生产 Web、Go API 和 PostgreSQL。管理员准备同项目的工单和讨论，另一名有贡献权的成员在 430 像素宽的 Chrome 中从工单详情进入「执行讨论」。[关联与权限合同](../../adr/0054-message-to-ticket-and-execution-discussion.md)

| 场景 | 实测结果 |
| --- | --- |
| 从工单选择讨论 | 成员从活跃频道第二页选中讨论，Web 读取讨论端关联能力，明确确认后才发出 POST。工单端和讨论端均能读到对应关系。 |
| 写入后丢失响应 | 服务端首次返回 201，浏览器丢弃这次响应。成员重试，第二次 POST 的参数和操作标识逐项相同，返回 200。双向列表各有一条关系，重新打开选择器时该候选标为已关联。 |
| 并发重复关联 | 成员选好另一条讨论后，管理员先关联了它。成员提交得到 409，页面重读后显示已有关系，数据库经正式列表读回仅一条。 |
| 撤销私密讨论读权 | 成员核对私密讨论后，管理员移除其 Thread 成员资格。确认提交返回 404，候选标题消失。管理员读回工单列表，确认该关系未写入。 |
| 归档与解除 | 成员选中私密频道的一条讨论后，将本轮隔离数据库中该合成频道设为归档。提交返回 409，重新打开选择器时频道标明已归档且禁选。成员仍可阅读并通过原 EntityLink ID 解除同频道另一条已有关系。 |
| 只读成员 | 管理员将成员的 Project 角色调为 viewer。刷新后可以打开可读关联，新增和解除按钮均已隐藏。 |

归档状态由测试夹具直接准备。创建、授权、关联、撤权、读取和解除均使用正式接口。界面只预先标记已加载页中的已知关系，分页外或并发重复由原命令检查。[组件测试](../../../web/src/collaboration/ExecutionPanels.test.tsx) · [频道选择器测试](../../../web/src/collaboration/ProjectThreadPicker.test.tsx)

`./scripts/check-web.sh` 最终通过 49 个文件的 329 项测试、格式、Lint、类型、生产构建和依赖检查。首次全量运行有一项登录焦点回归失败，该用例单独复跑和全量复跑均通过。Vite 仍提示主 JS 包超过 500 kB。仓库基线使用 `./scripts/check-repo.sh` 核验。
