# ADR-0061：频道内的可读讨论列表

状态：已接受

日期：2026-11-23

## 背景

成员需要从已进入的频道直接打开已有讨论。[ADR-0060](0060-message-started-thread-lookup.md) 确定了单条源消息发起的讨论与该消息所属讨论各自的含义。

## 决定

新增 Session 只读 `GET /api/v1/workspaces/{workspace_id}/channels/{channel_id}/threads`。每一页都在独立的数据库快照里检查当前 Workspace、Project 和 Channel 的读权。viewer 可读，归档资源沿用历史读权。

一行对应一条有效的 `Thread started-from Message`。来源消息与目标讨论均须属于当前频道。若来源是回复，成员还须能读它所属的 Thread。对来源所属 Thread 和目标 Thread 分别应用既有读权：继承项目可见性的讨论可读，私密讨论需要该成员的显式授权。任一条件不成立即略过该行。

返回 `data.items` 和 `data.next_cursor`。每行仅含 `ref`（`type=thread`、`id`）和 `title`。仅接受 `limit`（整数 1–50，默认 25）和 `after`。按 Thread ID 的 ASCII 字节升序，在权限过滤后取一页；仅发现额外可读行时才以本页末行产生下一页游标。游标绑定列表类型、Workspace、频道、成员及末行 ID。错误查询及不匹配的游标返回 `400`。

翻页沿用 ID 边界，重新检查当前读权，即使边界行已失权也能继续。翻回上一页重新读取。单条失权后略过；空页返回 `200`、空数组和空游标。频道、所属项目或 Workspace 不可读与资源不存在同为 `404`；会话失效返回 `401`。Web 切页时清掉上一页标题和链接，重新进入频道从第一页读取。响应使用 `private, no-store`。

## 替代方案与后果

复用逐消息查询会让发现成本随频道历史长度增长，并使每条消息分属不同的权限快照。直接查询已有来源关系可以一次取得可读页。稳定 ID 分页适合浏览；并发新增且排序在游标之前的讨论，可在重新读取首页时发现。

## 迁移与验证

复用已有来源关系、成员表和 Thread 详情，无需迁移。使用合成账号验证双端读权、翻页和回退、撤销单条及频道读权、空页和重新进入频道。
