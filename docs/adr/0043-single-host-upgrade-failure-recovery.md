# ADR-0043：单机停机升级与失败恢复

状态：提议；仅设计，尚未实施或执行本矩阵

日期：2026-10-18

补充 [ADR-0005](0005-forward-only-postgresql-migrations.md)、[ADR-0010](0010-verified-postgresql-backup-and-restore.md)、[ADR-0016](0016-minimal-docker-compose-self-hosting.md) 与 [ADR-0024](0024-read-only-schema-readiness.md)。保留 forward-only、精确 schema 匹配、显式运维与空目标恢复合同，不引入自动 downgrade。试用准入和评估授权分别见[支持说明](../trial-support.md)与[待决事项](../evaluation-authorization-decisions.md)。

## 背景与现有合同核对

设计核对基线为 `171527f`，schema 018。已有技术证据证明分项升级与恢复，尚未证明运维人员能够在一次真实中断后判断数据库状态、恢复服务并避免双实例继续写入。本片提出受控非生产、单宿主、停机维护的最小闭环，不将其解释为生产灾备完成。

| 源码 / 合同 | 当前事实 | 本设计要求 |
| --- | --- | --- |
| [migration runner](../../server/db/migrations.go)、ADR-0005 | advisory lock 串行化；每个 migration 的 DDL 与 history 同事务，逐文件提交；拒绝历史漂移 | 单文件失败不能推导整个批次回滚；等待锁和提交确认丢失均须可诊断 |
| [migrate CLI](../../server/cmd/nexus-migrate/main.go) | 当前请求 context 为 2 分钟；runner 清理使用独立于取消的 context | 2 分钟不是已证明的全部清理硬上限；须实测中断、连接关闭、锁释放和后续可操作性，不先承诺耗时 |
| [readiness](../../server/db/readiness.go)、ADR-0024 | 比对全部 migration history，不检查任意手工 DDL，不锁升级，不拦截全部业务写入 | 不能把 ready / not-ready、进程存活或退出码当作唯一升级状态 |

这些是源码与已有记录的核对，不是本 ADR 的故障演练结果。未修改代码、schema、部署配置或根许可证。

## 推荐范围与交付

首个正式版本对采用本地已有 `333c4ce` / schema 017 → `171527f` / schema 018，app、operations、Web 和配置分别留存准确工件身份。该版本对便于验证真实角色代次与邀请迁移；并不代表已发布版本或对外支持所有 017 实例。

环境限定为选定并实际验证的一台宿主上的独立 Compose 测试项目、固定 PostgreSQL 17 与工具、受限网络和同源 HTTPS。不拉取缺失依赖、不修改真实实例、不默认导入系统证书；后续资源启动、构建下载、故障注入、清理与具体目标仍需执行授权。

后续获准实施时交付一份可执行运维手册、复用现有 migration / backup / restore 的隔离演练入口，以及按本矩阵记录的证据。先验证既有能力；若发现中断处理或清理有缺陷，限定修正该路径并回归，不通过放宽 history、TLS、空目标限制或隐藏重试通过验收。不为演练增加假的业务 migration，不新建平行备份格式、许可服务、升级管理数据库或通用运维平台。

首片不交付跨 major、PITR、在线 / 零停机升级、滚动兼容、任意中间版本运行、自动 failover、生产容量、通用 forward repair 工具或全部数据库角色最小权限拆分。forward repair 只保留为“另行审阅、验证并授权”的选择，不当作现成自动修复入口。

## 操作身份与准入材料

升级前由部署负责人维护一份私有操作记录，记录操作标识、目标实例标识 / Compose project / volume 映射、源与目标工件身份、完整 migration history 校验结论、备份时间与校验值、维护责任人、阶段结果和重新开放决定。此记录是运维证据，不进入业务 Audit / Activity，不改变产品协议；不记录凭据、正文、CA 私钥或完整连接串。

镜像 `:local` tag 不足以识别旧 / 新工件；必须记录实际 image ID 或不可变 digest，并保留相应构建源码、配置版本和工具。旧配置与旧 Web 也属于恢复材料，不能只保存一个 Go 二进制。数据库 Secret、CA / 配置信息及授权材料通过现有私密保管方式独立管理，数据库 manifest 不代为包含它们。

开始前必须确认：

1. 精确目标和隔离资源所有权；磁盘 / 内存空间、工具可用性、原始实例与恢复副本不会误连。
2. 已获维护窗口、停写与允许的数据取舍授权；维护者不会在未知状态下自动重启或开放服务。
3. 配套旧 / 新工件齐全；没有 history 漂移、未知手工 DDL 或未分类数据。发现异常先报告，不能改 history 冒充标准实例。
4. 所有写入来源清单完整：app 请求、已建立 SSE、Webhook / worker、定时 CLI、其他部署操作者。首批试用不启用外部 writer；若目标实际存在，先停止或隔离并记录，否则拒绝开始。
5. 支持负责人、备份保管、可接受停机与数据损失、验证责任人明确；这些是本次操作约束，不能从测试库耗时推导生产承诺。

## 停写、升级和重新开放

下列状态是运维流程说明，不是新建的持久化状态机或已实现命令。任何步骤证据不足，都停在隔离状态，不能跳转为成功。

| 阶段 | 操作与必须取得的证据 | 进入下一阶段的条件 |
| --- | --- | --- |
| S0 核对 | 核对目标、旧新工件、配置、history、可恢复材料和维护授权 | 准入项齐全，无未知漂移 |
| S1 停写 | 摘除公共入口，停止 app 与已列明 writer，等待或受控终止在途请求 / 事务；检查旧连接和自动重启风险 | 已证明没有继续写入的路径；未确认请求按实际结果核查，不因客户端断开就视为回滚 |
| S2 备份 | 在停写后，用匹配源版本的工具生成新备份目录；校验并在独立空目标完成匹配版本恢复演练 | 工件可恢复、必要配置 / 秘密材料可用，源库仍停写；记录备份时点与此前已确认业务事实 |
| S3 迁移 | 使用目标版本 operations 显式执行 migration；记录输出和实际已提交前缀 | history 与目标匹配，并检查本次关键 schema / 数据不变量；异常进入失败分类 |
| S4 隔离验收 | 启动匹配的新 app / Web，在仅验收者可访问的入口检查 readiness、登录、权限、业务来源与状态 | 正式用户路径通过，旧工件不会误连新库，浏览器完整重新加载；验收写入明确标识并记录 |
| S5 重新开放 | 部署负责人确认结果、数据取舍及唯一写入目标，再开放一个入口，观察错误与连接 | 普通成员可以独立使用，旧源 / 副本保持隔离，记录完成；保留回退材料至约定期限 |

S1 必须由实际停止 / 隔离与事务检查证明；Caddy 的 readiness 探测、Compose `depends_on` 和单次 `204` 不能代替。S4 的验收入口仍使用正确 HTTPS origin、Cookie / CSRF 和可信代理，不通过关闭安全校验测试登录。迁移不是网页 setup，已有实例不再次 bootstrap。

## 失败分类与恢复选择

| 观察到的状态 | 允许的后续选择 | 禁止推断 |
| --- | --- | --- |
| 尚未迁移，备份 / preflight 失败 | 保留旧库与工件，定位问题；确认旧实例完整后由负责人决定恢复旧服务或保持停机 | 不能因为旧进程能启动就忽略损坏备份继续升级 |
| 执行中、锁等待或客户端失联 | 保持隔离，通过独立连接检查 runner / 事务 / 锁和 history；必要的终止操作须确认精确目标 | 不能根据 CLI 消失、超时或网络错误推断已回滚，不能并发启动第二个修复者 |
| 确认本次失败 migration 未提交 | 校验其前序已提交 history 与关键 schema；排除残留 writer 后，可显式重新执行同一匹配目标工件完成剩余迁移 | 多 migration 批次中前面成功的版本不会自动回退；没有匹配运行工件时不能恢复旧 app |
| COMMIT 确认不明或已提交部分前缀 | 查询真实 history 与关键不变量，记录已提交范围；合法前缀可受控续迁，未知漂移停止调查 | 不手工补 history、不改 checksum、不把不确定状态变成默认成功 |
| 目标 schema 已完成，app / Web / 配置验收失败 | 修正已确认的部署配置或使用已验证的匹配新 schema 工件；若放弃则走旧备份空目标恢复 | 不把“换回旧镜像”当成数据库回退；即使旧 app 仍能处理部分请求也不允许开放 |
| 决定恢复旧版本 | 保留失败源库隔离，用匹配备份的旧工具恢复到新空目标，配套旧 app / Web / 配置完成验证后显式切换唯一入口 | 当前新工具不会自动兼容旧备份；恢复到旧版本与恢复后再升级是两个独立决定 |
| restore / Activity 重建失败 | 保留失败目标隔离和诊断摘要，另建空目标重试；清理只针对明确拥有且获准删除的测试资源 | 权威数据已恢复不等于目标可用；不原地覆盖、不自动删除源数据或成功备份 |
| 已开放或发生新业务写入后又需回退 | 立即重新停写，记录备份点后的事实和损失范围，单独确认数据取舍，再选择修复或恢复 | 原先停机授权不等于永久允许丢弃后续数据；本片不提供自动双向合并或重放 |

原库与恢复副本可能拥有相同业务 ID，因此不能依赖 user / Workspace ID 单独辨认目标。切换期间只允许一处接受用户写入，禁止原库和恢复副本同时开放。数据库 Secret 可以按目标环境重新配置，但不得为恢复降级 TLS、扩大网络访问或复制不明凭据。

恢复必须核对：实体与关系来源、权限、不可变 Audit / receipt、Document 版本、Ticket 状态以及重建 Activity；Session、邀请码和 OIDC 事务为空，需要重新登录。旧快照可能恢复旧密码 verifier 与旧 owner，后续操作记录也可能不存在，必须按快照事实重新核验管理责任，必要时另行执行有授权的账号恢复；不能自动重放交接、赋权或重开 setup。

若停写后备份且直到恢复均无后续业务写入，可以核对该备份点前已确认事实完整；这仍不是对任意故障的 RPO=0 承诺。备份后验收写入或重新开放后的写入均纳入取舍记录。分别测量停写、备份、迁移、恢复、Activity 重建和验证耗时，并记录数据量、宿主资源与连接规模；不预设生产 RTO。

| U28 | 成功或失败后的清理与材料保留 | 仅清理本轮明确授权资源，保留所需备份 / 工件 / 证据；用户实例、系统信任和远程状态不变 | 资源清单 + 最终核对 |

U11 使用隔离 runner 测试或经过核对的历史版本链证明逐条提交，不修改已发布 migration 或添加演示业务 migration。U08～U10、U19～U20 的注入位置必须证明真实发生在预期阶段；仅模拟一个错误返回不能证明数据库提交或恢复原子性。

后续执行记录必须逐项写通过 / 失败 / 未执行、环境、实际版本对和证据来源。没有普通用户浏览器和运维复验，不能仅凭单元测试宣称全链完成；没有生产规模与权限分工证据，不能升级为生产支持。

## 替代方案与取舍

| 方案 | 结论 |
| --- | --- |
| 继续只验证全新 Compose 或一次 dump / restore | 无法证明中断后状态判断与开放流程，不作为本片完成条件 |
| 靠 readiness 自动阻断升级期间的全部请求 | 探针不是写入锁，存在旧连接与探测间隔，不采用 |
| 数据库已变后只切回旧镜像 | 违反精确 schema 兼容合同，不采用 |
| down SQL / 原地覆盖 / 修改 history | 可能丢失事实并掩盖漂移，不采用 |
| 先做零停机、HA、PITR 或自动修复平台 | 超出单机非生产试用需要，延后独立设计 |
| 停写、验证备份、按实际状态续迁或空目标恢复 | 复用现有能力，成本是明确停机窗口、额外空间与人工判断；推荐首片 |

## 待确认与后续实施边界

所有者需确认推荐版本对、首个宿主环境、试用准入是否接受本停机模式，以及允许的最大停机 / 数据取舍和恢复材料保管责任；具体数值由测量与试用安排确定。提议接受后，另行授权隔离资源、故障注入及清理，再实现手册与必要演练入口。本提案仅形成设计，不授权启动实例、发布工件、签发授权或远程写入；文档提交不代表接受提案或实施授权。
