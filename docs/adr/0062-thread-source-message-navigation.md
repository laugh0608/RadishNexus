# ADR-0062：从讨论返回原消息及来源撤权

状态：已接受

日期：2026-11-23

## 背景

成员从频道列表打开讨论后，需要回看发起它的那条消息。消息可以是频道里的顶层消息，也可以是另一私密讨论的回复。子讨论的成员资格和父讨论的读权分别生效。[频道讨论列表](0061-channel-thread-discovery.md) · [单条来源查询](0060-message-started-thread-lookup.md)

## 决定

2026-11-23，所有者确认保留当前可读的子讨论，隐藏失权来源。沿用既有 Thread Nexus View 的完整和 summary 两种读取模式，以及已有的单条消息 GET。

| 当前条件 | 详情和导航 |
| --- | --- |
| 子讨论、来源消息及其所属讨论均可读 | 返回既有可读 `started-from` 关系。Web 在来源行提供「打开原消息」。按来源频道和消息 ID 读取，顶层消息在频道定位，回复按本次读取返回的父 Thread 在其详情中定位。 |
| 子讨论可读，来源回复所属的 Thread 已失权 | 两种详情均返回 `200`。唯一来源只含 `{"visibility":"restricted"}`。该行没有定位链接、来源引用、父 Thread ID 或消息正文。 |
| 当前 Thread、所属 Channel 或 Project 不可读 | 详情沿用 `404`。单条消息读取按自己的当前权限判断；旧地址和浏览器后退均要重新鉴权。 |
| 既有 Thread 没有来源频道 | 详情仍无来源关系，页面没有原消息入口。 |

[ADR-0019](0019-session-scoped-thread-decision-ticket-transport.md) 对可读来源的字段和基数继续适用。只接受现有权限投影产生的纯受限占位；缺失来源、重复来源、受限项携带字段仍是合同错误。频道发现沿用双端读权，只有子讨论读权时仍可从已有合法入口重读该讨论。

## 实施与验证

复用不可变的来源关系、数据库快照内的权限投影，以及已有消息定位页。详情不预取正文。Go 与 Web 同步接受受限来源，旧版严格客户端在这一情形仍会报告读取失败。无需迁移。用合成账号核对顶层与回复的准确定位、来源和目标分别撤权、重新进入，以及已打开的旧链接。
