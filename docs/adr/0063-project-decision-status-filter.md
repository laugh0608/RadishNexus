# ADR-0063：按状态浏览项目决策

状态：已接受

日期：2026-11-23

## 背景

成员需要在项目中跨页找到待确认提案。现有项目决策列表按稳定 ID 展示四种状态，逐页在浏览器中过滤会漏掉尚未加载的提案。[项目决策发现](0040-project-decision-discovery.md) · [拒绝](0048-decision-lifecycle-and-rejection.md) · [替代](0049-decision-supersession.md)

## 决定

在既有 `GET /api/v1/workspaces/{workspace_id}/projects/{project_id}/decisions` 上接受一个可选 `status` 参数，取值为 `proposed`、`accepted`、`rejected` 或 `superseded`。省略表示全部状态；空值、重复、组合值或未知状态返回 `400 invalid`。每项仍只含 `ref`、`title`、`status`。

每页在同一数据库快照检查 Project 读权，然后按当前状态过滤，再按原 Decision ID 顺序取 `limit + 1` 条判断有无下一页。默认 25 条、上限 50 条。来源私密的 Decision 仍按自身所属 Project 发现。归档项目沿用历史读权；失去 Project 读权返回 `404`，会话失效返回 `401`。列表中的「待确认」表示 Decision 的状态，接受或拒绝仍在详情中由既有命令独立鉴权。

无筛选请求沿用 ADR-0040 的 v1 游标及其原编码。筛选页使用同一游标的可选 `status` 字段，绑定 Workspace、Project、列表类型、状态及最后返回的 ID。切换状态、从全部切入筛选或反向复用游标均返回 `400`。边界决策变更状态后仍按 ID 继续，后续请求读取当前状态；移入已翻过区间的决策可在刷新首页后找到。

Web 默认展示全部。切换筛选时立即移除旧行、取消在途请求，并从新状态的首页读取。前进和回退沿用当前筛选，页内刷新保留选项并从该筛选首页重读。重新打开项目列表从全部状态开始。

## 替代方案与验证

沿用原发现接口可以共用既有准入、分页与错误处理，无需新增表、迁移或写权限。合成账号验收覆盖跨页筛选、状态变化、游标兼容、私密来源和撤权后的页面。
