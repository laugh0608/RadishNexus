# ADR-0036：同一官方客户端连接官方与自部署实例

状态：已接受的产品与客户端规划；实现未开始。

日期：2026-10-12（Asia/Shanghai）。

## 背景

RadishNexus 已确认 Web-first、自部署优先和后续 Flutter mobile / PC，但此前没有明确官方端点与同一安装包的服务器选择。仅有 Compose 或可配置部署域名，不能证明用户无需重编译就能在官方客户端连接自己的实例。

项目所有者本次明确要求先统一 Radish、RadishLex、RadishMemory、RadishNexus 四个产品的规划，仅修改文档。

## 决定

- 官方端点纳入产品交付目标；同一官方 Flutter 安装包在运行时支持官方端点和用户自部署的兼容后端，无需重新编译。
- Web 使用相同官方构建产物，在各实例同源 HTTPS 入口交付；不新增官方托管 Web 的跨域 Session 连接模式。
- 自部署核心路径保持独立，不依赖官方云在线，不引入席位或在线许可证门槛。
- 连接前检查兼容性，实例与 Workspace 分离，认证、凭据、缓存、离线队列和引用按实例隔离；切换不自动迁移或重放数据。
- 具体流程、待冻结协议、实施切片与验收以[客户端连接规划](../architecture/client-server-connection-plan.md)为详细来源。

本 ADR 补充产品交付方向，不替代 ADR-0013 / ADR-0015 的当前 Web transport，也不提前修改认证、权限、schema、技术栈或许可证。

## 替代方案

仅允许官方端点会破坏自部署客户端目标；为每个实例重编译或重签名会增加分发与维护负担，也不满足同一官方安装包要求。让官方 Web 任意跨域携带 Session 会改变已接受的同源边界，不作为本轮方案。

## 后果

发布与客户端验收需增加实例选择、兼容窗口、凭据 / 离线状态隔离及同一安装包双目标证据。官方托管的域名、运营、配额与真实服务验收需独立完成；确认方向不表示这些能力已经上线。

Web-first 与 M7 门槛继续有效，当前阶段不启动 Flutter 或部署。第三方重写后端兼容支持、跨实例数据迁移和多实例同时在线不由本决定自动取得实施范围。

## 迁移与验证

本轮无代码、配置或数据迁移。未来单实例缓存与离线状态只能绑定已知原实例，不能自动归给新的服务器。实现前冻结实例标识、发现、TLS、原生认证和持久化迁移，再在同一候选安装包上完成两个独立实例验证；两类路径按实际开放范围分别取得真实目标证据；官方未上线不额外阻塞兼容自部署验收，完整双端点交付需两侧证据。
