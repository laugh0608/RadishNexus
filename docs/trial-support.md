# 受控试用支持说明

核对基线：`94da10d`，schema 020；范围与授权仍待确认。本文定义首批试用拟支持什么、如何求助、何时停止及如何退出；当前执行顺序仍以[当前状态](status/current.md)为准。使用权取决于根 [LICENSE](../LICENSE) 与另行有效的书面授权，本文不授予部署或运行权。授权范围待决事项见[评估授权设计](evaluation-authorization-decisions.md)。

## 推荐首批范围

| 维度 | 拟支持的最小范围 | 限制与待验证项 |
| --- | --- | --- |
| 用途与数据 | 受邀主体内部、非生产、可重建的协作练习；真实需求使用合成或充分脱敏材料表达 | 不作为唯一业务记录，不放生产秘密、个人敏感信息或无权提供的材料；真实敏感业务数据需另行审查支持与数据边界 |
| 拓扑 | 一台明确选择并实际验收的宿主，单 Go app、单 PostgreSQL 17、Caddy 同源 HTTPS；一个试用 Workspace | 首片沿既有 Compose 模式；候选宿主的 OS / CPU / Docker / Compose 版本必须填实并复验，不能先写成 Linux / macOS / Windows 全支持 |
| 工件 | 一个固定候选 commit 对应的 app、operations、Web、配置与数据库工具；记录镜像实际身份 | `94da10d` 只是源码核对基线，不是已发布版本；`:local` tag 可被覆盖，不能独立作为工件身份 |
| 网络与证书 | 部署者控制的受限网络、单一精确 HTTPS origin、受控 internal CA 信任 | 不关闭 TLS 校验或扩大代理信任；公网域名 / 公共证书、远程 TLS 数据库工具桥接另验 |
| 账号与权限 | 本地邮箱登录、正式邀请、owner 与对象级角色；受控部署者负责恢复 | 人员变化使用明确的暂停 / 恢复 / 退出与再邀请流程，不把“降为 member”当作离职撤权；owner 不继承私密对象或 Deployment 显式权限 |
| 协作场景 | Message → Thread → 人工确认 Decision → Ticket 状态流转 → Markdown Document，并从 Project 找回对象 | 不宣称完整 Golden Path；真实 Jenkins / OIDC、Flutter、CRDT 与中文原生 IME 按各自停止线处理 |
| 客户端与规模 | 选定桌面浏览器及需要的手机视口；记录连接数、多标签页、对象数量、数据量和耗时 | 已有 Chrome / 390px 视口证据不是全部设备兼容或容量承诺；不设许可席位数，不把 5～200 人目标假设当作已验证容量 |
| 运维 | 部署者执行备份、停写、授权范围内的恢复；维护者提供约定范围的 best-effort 协助 | 不自动升级，不承诺零停机、固定恢复时间或无数据损失；升级失败流程已有 [ADR-0043](adr/0043-single-host-upgrade-failure-recovery.md) 隔离证据，独立操作者及目标环境复验仍待完成 |

首批不承诺多副本 / HA、跨 PostgreSQL major、跨 schema 滚动兼容、PITR、在线迁移、任意第三方改造或生产运维托管。变更范围先重新确认支持条件，不把未验证配置自动纳入支持矩阵。

## 责任与故障报告

| 责任主体 | 必须明确的责任 |
| --- | --- |
| 项目所有者 / 维护者 | 确认试用范围、候选工件和支持联系；审批实际使用授权；说明已知问题；决定修复或暂停建议。收到问题不等于承诺修复期限 |
| 试用部署负责人 | 保管宿主、数据库和备份权限；核对目标实例；处理 CA 信任与配套配置；批准停写、数据取舍和重新开放；独立保管秘密材料 |
| Workspace owner | 按正式入口邀请和配置成员、确认交接；不代替全局账户恢复或宿主运维授权 |
| 参与成员 | 在约定数据范围内操作；报告复现步骤与影响；不向公开渠道上传私密内容 |

普通可公开缺陷沿用仓库缺陷模板；无法公开的运维问题先通过约定私密联系说明材料种类，再安排传输。涉及越权、泄漏或未修复漏洞时严格使用 SECURITY.md 的渠道，不因普通支持未回复而公开细节。现有许可证申请邮箱可用于授权申请，不因此自动成为全天候技术支持热线。

报告最小材料：commit / app 与 operations 工件身份、schema 版本与 history 校验结果、宿主与浏览器版本、发生时间及操作阶段、影响范围、稳定错误码 / request ID、最小脱敏复现、是否仍在写入、备份时间与是否有备份后业务写入。只提供必要摘要；不附完整数据库、私密正文、密码 verifier、Cookie、CSRF、邀请码、DSN、Secret 文件或 CA 私钥。原始日志不能因标注“诊断”就直接上传；本片不建设自动诊断包或遥测。

发现授权异常、疑似数据损坏、无法确认升级状态、不可验证备份或超出约定数据范围时，部署负责人先停止受影响写入并保留证据，联系维护者。生产事故响应和完整失陷处置仍需独立设计；不得自行删库、改 migration history 或以恢复旧备份掩盖失败。

## 数据、备份与退出

每次试用开始前，私下记录数据责任人、备份位置、访问者、频率、保留期、恢复目标、可接受数据损失和最大可接受停机窗口。这些值本轮不预填为承诺；须结合实际测量与维护能力确认。宿主上的默认备份目录不是离机备份策略，磁盘满或宿主丢失不因存在 dump 就已被覆盖。

数据库工件含密码 verifier 和业务授权，按敏感运维材料管理。数据库 Secret、Caddy 私钥、部署配置和实际授权材料不由整库备份自动恢复，部署者须有独立的受控保管与重建安排，不将其纳入普通诊断附件。

退出时由部署者与数据责任人核对保留 / 删除范围、停止对外访问和备份交付方式。现有可验证路径包括受控整库备份与匹配工件空目标恢复，以及 ADR-0044 的单 Project 协作上下文包；后者不覆盖完整 Workspace / 研发实体 / 附件，也不提供自动删除或一键迁移到其他产品。到期后的软件使用与数据取回权利须写入最终授权；产品不因授权状态删除、加密或扣留数据，具体法律条件见待决事项。

观察记录只收集任务完成情况、重复录入、追溯是否可用、维护者介入次数、失败与恢复耗时及数据规模。真实参与者和私密内容保存在受控位置，仓库只收录脱敏结论；不把参与记录变成成员数量许可限制。

## 准入与退出判据

下表是未来试用准入检查，全部待执行或确认，不是本轮已通过验收。检查缺项时不邀请外部主体实际运行；文档设计完成不替代有效授权。

| 编号 | 准入项 | 必需证据 |
| --- | --- | --- |
| T01 | 范围、参与主体与数据边界 | 所有者、部署负责人和数据责任人确认的私下安排；不记录成员数许可条件 |
| T02 | 软件使用权 | 经复核的有效书面授权与版本 / 用途范围；不是本草案或公开演示链接 |
| T03 | 环境与工件 | 精确宿主 / 工具 / 浏览器清单，完整匹配的工件身份及必要旧工件留存；目标环境实际复验 |
| T04 | 正式用户路径 | 普通成员独立登录、发现与协作、权限拒绝、账号恢复与主动交接；已知限制已告知 |
| T05 | 支持与报告 | 已确认的联系人、联系时段与预期回复安排；普通问题 / 私密问题分流和脱敏示例可用 |
| T06 | 可恢复性 | 实际备份 / 空目标恢复与 ADR-0043 对应矩阵通过；操作方能依据状态处理，不依赖手改数据库 |
| T07 | 数据取舍与测量 | 可接受停机 / 数据损失与实测耗时、数据量、连接规模分别记录；不把目标值当作测量结果 |
| T08 | 暂停和退出 | 停写决策人、证据保管、终止联系、授权到期安排与现有数据取回方式明确 |

受控试用结束时由所有者决定继续、修复后重试或退出，不能把试用自动续成生产支持。数据库最小权限、完整安全审计查询与保留、数据生命周期、生产容量及结构化导出仍按路线图独立验收。
