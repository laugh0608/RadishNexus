# 评估授权待决事项

状态：待决事项与推荐方向；不是授权模板、法律条款或已签发授权

日期：2026-10-18

依据根 [LICENSE](../LICENSE) 第 2～4、9～10 节及[许可策略](licensing-strategy.md)。本轮只把所有者和专业复核需要解决的问题列清，不改变根许可证、不授予实际运行权、不向任何人签发或发送授权。

## 已有边界

- 现行根许可证只提供其明确列出的查看 / 学习权利；实际部署、运行、复制、修改等依赖另行有效的书面授权或适用组件许可证。
- 所有者可以免费单独授权；授权主体和条件须明确，不按用户、成员、访客、频道、项目、文档或工单数量建立收费或功能门槛。
- 自部署核心不依赖官方云、持续联网校验、席位 Token、遥测或官方账号；产品不因授权状态扣留或毁坏数据。
- 第三方和另行许可组件保持其自身边界，不能由核心授权文案代为扩大其权利。
- 许可策略要求首次对外授权前形成独立模板并接受专业法律审查。本文件仅整理项目已有要求与候选选择，不评价条款在特定司法辖区的法律效力。

## 推荐首片

先采用“指定主体的免费书面非生产评估授权”作为待确认方向，复用现有申请联系渠道；不先改根许可证为公开评估许可，也不建设自助签发、授权导入校验 UI 或激活服务器。离线材料的签发、留存和人工核对可以先独立于软件运行；这不表示当前产品已经实现机器可验证的授权文件。

申请人先看[受控试用支持说明](trial-support.md)，以最小信息提出申请；维护者确认受支持条件后，形成经过复核的具体授权，再由所有者决定是否签发。书面授权、技术准入、宿主操作授权与数据处理同意各有范围，不能相互替代。专业复核可与升级恢复设计同时推进，但外部实际运行须等待所需前提完成。

## 最小交付物与退出条件

本轮交付的是上述待决事项。后续获授权后再准备：

1. 面向申请者的一页评估说明：最小申请信息、渠道、回复预期、支持范围与已知退出限制。
2. 经所有者选择与专业复核的书面授权模板：消除 E01～E12 歧义，明确引用的支持文档版本；模板自身不代表对某主体签发。
3. 私下签发与留存流程：确定签发权限、记录字段、交付 / 接受和后续变更方式；不新建产品许可数据库或线上授权服务。

用一个合成申请场景桌面走查“获取工件 → 构建 → 运行 → 备份 → 恢复副本 → 到期取回 → 结束”；每一步都能对应明确许可范围和现有技术能力，材料不含成员数、秘密或真实主体信息。签发前须完成专业复核与具体主体确认；尚未解决的条款不能用默认值填补。

本文件不触发法律服务采购、联系申请者、发送邮件、远程设置或授权签发。若推荐方向获确认，后续仍分别授权模板准备、签发和试用实例操作。
