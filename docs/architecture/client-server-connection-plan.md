# 官方客户端与实例连接规划

状态：产品方向已确认；Flutter 与运行时实例选择尚未实施。

确认日期：2026-10-12（Asia/Shanghai）。

本文面向产品、Web、Flutter、身份与发布维护者，定义同一官方客户端连接官方端点和用户自部署实例的产品范围、切换与验收。决策依据为 [ADR-0036](../adr/0036-official-client-instance-connection.md)；具体发现协议、原生认证 transport、存储 schema 与域名在实施前另行冻结。

## 产品交付目标

同一平台、同一正式发布渠道的同一个官方 Flutter 安装包，必须在运行时支持“官方服务”和“自部署服务器”。用户填写并保存兼容 RadishNexus 实例地址即可使用该实例，无需修改源码、重新编译、重签名或取得实例专用安装包。

官方端点纳入正式交付目标；真实域名、开放时间、运营资源与服务范围单独确认。自部署核心运行、授权、备份与恢复不依赖官方端点在线，也不因此引入席位限制或在线许可证检查。现行 LICENSE 与书面授权流程不由本规划改变。

首期仍是 Web-first；Flutter 的 mobile / PC 实施继续遵守 M7 启动条件。本方向不把当前 Web 原型或 Compose 验证描述成官方托管服务已上线。

## Web 与安装客户端

- 官方与自部署实例可交付同一官方 Web 构建产物，按各自域名的同源入口提供页面、登录和 API；更换实例域名不要求重编译前端。
- 用户在浏览器访问目标实例。官方托管 Web 跨域携带 Session 连接任意服务器不属于本轮范围，ADR-0013 / ADR-0015 的 HTTPS public origin 和同源认证边界继续有效。
- Flutter 提供登录前的运行时服务器选择，再进入目标实例的登录、Workspace 发现和业务操作；实例不是 Workspace，也不是 Project 或业务 Environment。
- 原生认证 transport、安全凭据存储和退出生命周期在 M7 实施前评审，不将浏览器 Session 的现有测试直接当作 Flutter 证据。

## 连接与切换流程

1. 用户选择官方服务或填写自部署地址，界面展示目标归属和当前服务器。
2. 发送登录凭据前验证地址、TLS、实例身份、协议兼容性和能力；发现请求有超时与响应上限，不携带其他实例凭据。
3. 按该实例实际启用的认证方式登录，再按本地用户与 current membership 发现 Workspace。选择实例不授予成员资格、管理员权限或插件授权。
4. 切换前处理未保存 Document、待发消息与未完成命令，停止旧实例实时连接和后台请求。
5. 新实例独立建立会话；旧响应、深链、实时事件、离线草稿及 pending action 只在其所属实例消费。

会话、凭据、缓存、离线编辑队列、通知、附件与对象引用都按实例和账户隔离。相同邮箱、issuer / subject、Workspace ID 或对象 ID 不表示跨实例属于同一身份或资源，不能自动合并或重放业务写入。

切换地址不是数据迁移，不自动复制 Document、消息、Secret、权限、插件授权或 CI/CD 配置。未来迁移继续遵守已有导出、备份与授权材料边界，不把改地址变成外部执行或部署批准。

## 兼容性与安全

正式远端连接使用验证有效的 HTTPS；局域网地址、端口、证书信任与原生 callback 策略在实施前冻结，不以永久忽略证书错误提供自部署支持。

兼容发现应说明协议范围、最低客户端 / 服务端要求、认证及能力可用性。版本不兼容、服务维护、登录取消、证书错误或断线有明确状态；不自动回退官方端点、不扩大成员权限，也不向另一 origin 转发旧凭据。

官方与自部署维护相同公开兼容协议。精确发现路由、Dart API 维护方式、认证 transport 和兼容窗口仍是后续工程决策，不能由本规划推定当前 Web Session 合同已经覆盖原生客户端。

## 实施顺位

当前 Web Golden Path、M1 基础与已激活交付任务继续按[当前状态](../status/current.md)推进，不因文档更新提前启动 Flutter、官方部署或外部服务。

后续按产品路线分开交付：

1. 在 Web / 服务端协议稳定过程中评审实例身份、能力发现、版本兼容、公开部署配置与官方运营边界。
2. 达到 M7 条件后建立 Flutter 服务器选择、实例绑定与原生认证，保持一个明确的活动实例；多实例同时在线不作为首个切片前置。
3. 接通业务 HTTP / realtime、账户与离线状态隔离，验证重启、切换、失权与失败恢复。
4. 同一候选安装包完成官方及自部署独立目标验收，并分别取得真实服务和自部署安装 / 升级 / 备份恢复证据。

## 验收标准

- 同一个未改动官方安装包选择官方端点和独立自部署实例，完成登录、Workspace 发现、消息 / 工单 / 文档的首期操作、退出、重启与切换。
- 官方与自部署路径按实际开放范围分别取得真实目标证据；官方尚未上线可独立验收自部署路径，未验收一侧明确标记未开放。完整双端点交付需两侧证据，两个临时测试实例只证明客户端机制。
- 旧实例 Session、凭据、缓存、实时事件、离线草稿与对象引用不会进入新实例；相同对象 ID、延迟响应与切换期间失败覆盖负向验证。
- 官方服务不可用不影响兼容自部署选择；未保存内容有明确处理结果，不自动迁移或执行原实例 pending action。
- Web 保持实例同源边界；每个承诺支持的 Flutter 平台独立取得认证、持久化与运行证据。
